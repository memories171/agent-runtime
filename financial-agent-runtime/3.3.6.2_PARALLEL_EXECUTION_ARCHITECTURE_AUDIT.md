## 0. 审计结论

**最终判定：FAIL**

Phase A 存在 2 个 P1 阻断项：

1. **P1-1 数据正确性**：`ExecutionMetricsService._load_scope()` 以调用方传入的 `root_run_id` 作为图遍历种子；若该 root 位于另一个连通分量或没有任何 delegation 边，整棵目标子树会被静默丢弃，接口仍可能返回 `data_quality=OK` 的全零指标。

- **不建议启动 3.3.6.3。**

## 4. 六维度审计结论

### A. Parallelism 数学正确性 — **不通过**

核心算法基本正确：

- 半开区间 `[started_at, completed_at)`：`parallelism.py:64-71,118-134`
- 同时间戳 delta 聚合：`parallelism.py:133-143`
- 窗口裁剪：`parallelism.py:125-134`
- UTC 归一化：`parallelism.py:19-23,73-75`
- average 分母为查询窗口长度：`parallelism.py:79,157`
- attempt 不按 node 去重：`parallelism.py:92-97`

但存在边界缺陷：

- `current_parallelism` 可大于 `max_parallelism`。
- open interval 在 `started_at > now` 时同时计入 `partial_interval_count` 与 `unknown_interval_count`。
- `now == window_start` 时 open interval 被完全丢弃，而跨窗口的终态区间仍被计入，语义不对称。
- `test_empty_collection` 中存在恒真断言，不能作为有效验证。

详见第 5 节 P2-1 至 P2-3。

### B. Tree Integrity — **不通过**

已实现：

- ROOT_MISSING：`metrics_service.py:210-212`
- ROOT_MISMATCH：`metrics_service.py:213-215`
- CYCLE_DETECTED：`metrics_service.py:108-132,200-204`
- DUPLICATE_CHILD_LINK：`metrics_service.py:97-99,196-198`
- AMBIGUOUS_PARENT_CHAIN：`metrics_service.py:151-154,205-208,224-236`
- CROSS_TENANT_OR_MISSING_RUN：`metrics_service.py:217-220`
- 深树使用迭代式遍历，无 Python 递归深度风险。

但存在 P1-1：错误 root 跨连通分量时静默返回全零 `OK`。此外：

- ORPHAN 无独立 reason；
- ROOT_MISMATCH / ROOT_MISSING 不参与排除，仍计入指标；
- ROOT_MISSING 与 0016 的 `MAX_HOPS=1024` 语义冲突；
- 全租户无界加载导致无关树的异常可能影响当前 reason code。

### C. ACL 和 Tenant Isolation — **不通过（因 anomalies 端点）**

Metrics 路径本身基本正确：

- tenant 只取 `principal.tenant_id`：`monitoring_api.py:112-118`
- service 显式校验 tenant：`metrics_service.py:363-364`
- Root ACL：`monitoring_api.py:111` → `_owned_run()` → `api.py:104-121`
- Child 逐 Run ACL：`metrics_service.py:277-283,373-377`
- 无 Parent ACL 继承：`metrics_service.py:373-377`
- 隐藏 Child 不进入聚合：`metrics_service.py:373-382`
- 响应只含通用 reason code：`contracts.py:177-197`

但 `/tree/anomalies` 端点存在 P1-2 ACL 结构泄露。

另有观察项：

- `auth.py:138-141` 把 JWT `permissions` claim 合并进 `principal.permissions`，`can_access_run()` 依赖 `runs:read:tenant`；需确认 IdP claim 白名单，否则是租户内跨用户权限边界风险。该项非 Phase A 引入，但与本次 ACL 审计相关。

### D. Delegation 生命周期 — **通过但带条件**

状态语义与 Metrics 映射基本一致：

- `RUNNING / WAITING / CANCEL_REQUESTED` 视为 active：`parallelism.py:15,103-108`
- `ISSUED / CHILD_STARTING` 不计入：`parallelism.py:16,100-101`
- 终态必须有有效 completed_at：`parallelism.py:109-113`
- CANCEL_REQUESTED 非终态语义保留：`orchestration/models.py:32-33`

但发现既有问题会影响指标解释：

- `settle_terminal()` 可绕过 `DELEGATION_TRANSITIONS`：`delegation_service.py:343-357`
- `mark_cancel_requested()` 可绕过状态机：`delegation_service.py:308-317`
- `mark_started()` 对已 RUNNING 记录非幂等，配合 Activity retry 可能失败：`delegation_service.py:258-263` + `orchestration/runner.py:247-252`
- `WAITING` 状态当前生产路径无写入者，metrics 对 WAITING 的处理目前是定义层面的，不是实际观测层面的。

### E. 性能与扩展性 — **通过但带条件**

本次独立复测：

| delegation records | elapsed |
|---:|---:|
| 10 | 2089.69 ms（冷启动） |
| 100 | 21.95 ms |
| 1,000 | 69.77 ms |
| 10,000 | 717.61 ms |

架构特征：

- 不是 N+1；metrics service 主查询为 2 次 bulk load。
- 但每次请求全 tenant 加载 delegation：`metrics_service.py:256-259`
- 再构造全 tenant run id 的 `IN (...)`：`metrics_service.py:261-273`
- 内存中构建多份 O(D+R) 结构：`metrics_service.py:275-311`
- `hits_cycle()` 与二次父链遍历在深链/宽图组合下可退化为 O(D×L)：`metrics_service.py:170-178,224-236`
- 100K 平坦图约有 100,001 个 run id，存在 PostgreSQL bind 参数超限硬失败风险。
- 无 statement timeout、rate limit、cache 或 bulkhead。
- 10K 星形图测试不能支持 100K 或并发生产容量结论。

当前代码证据显示：

- 未新增 Workflow signal / query / command / Activity。

## 5. 已发现的问题及证据

### P0

无。

### P1

#### P1-1 跨连通分量错误 root 导致静默漏算并返回 OK

证据：

- `src/agent_runtime/monitoring/metrics_service.py:293`：`queue = deque([_key(root_run_id)])`
- `metrics_service.py:301-305`：`scope_records` 只来自以该 root 为种子的 BFS component
- `metrics_service.py:399-400`：空 scope 不加入任何 reason
- `metrics_service.py:91`：`root_key` 计算后未使用

场景：

1. 用户请求真实树 root R1，但误传同 tenant 另一个无 delegation 的 run R2。
2. component 只包含 R2。
3. `scope_records` 为空。
4. 不触发 `NO_VISIBLE / INCOMPLETE_SCOPE / ROOT_MISMATCH`。
5. 响应为全零指标且 `data_quality=OK`。

另一个场景：误传另一棵独立树的 root，会返回那棵树的指标，仍为 OK。

影响：监控面给出确定错误的“没有并行 Agent”结论，属于数据正确性阻断项。

建议：整改时必须验证请求 root 是否是被解析出的组件真实根；无法确认时返回 UNAVAILABLE 并给出通用 reason，而不是返回 OK 全零。

#### P1-2 `/tree/anomalies` 端点泄露隐藏 Child 结构信息

证据：

- `src/agent_runtime/monitoring_api.py:82-86`：只检查 Root ACL，未传 principal 给 anomalies 服务
- `src/agent_runtime/orchestration/delegation_service.py:563-629`：`detect_tree_anomalies()` 无 ACL 过滤
- `delegation_service.py:589-592`：返回 `orphans` Child UUID
- `delegation_service.py:606`：返回 cycle 路径 UUID
- `delegation_service.py:624-628`：返回 duplicate child UUID
- `src/agent_runtime/contracts.py:170-174`：契约声称 ACL filtered，与实际不符

影响：只拥有 Root 读权限的用户可枚举同 tenant 内其他 user 的隐藏 Child ID 与关系结构，违反隐藏 Child 信息不泄露要求。

建议：在公开 API 中移除或完全泛化该端点；若保留，必须逐 Run ACL 过滤，且不得输出隐藏节点 UUID、路径或数量。

### P2

#### P2-1 `current_parallelism > max_parallelism`

证据：

- `parallelism.py:107` open interval 终点为 `min(now,window_end)`
- `parallelism.py:140-143` delta 扫描在 now 处已应用 open interval 的 -1
- `parallelism.py:147-150` current 对 open interval 只判断 `interval_start <= current_time`

只读复现：

```text
A: RUNNING started_at=START+20
B: COMPLETED started_at=START+30, completed_at=START+40
now = START+30

P2-1 current= 2 max= 1
```

影响：同一响应内部数学不变量被破坏。

#### P2-2 active 记录同时计入 partial 与 unknown

证据：

- `parallelism.py:103-108` 先 `partial_interval_count += 1`
- `parallelism.py:118-121` 后因 `interval_end < interval_start` 又 `unknown_interval_count += 1`

只读复现：

```text
RUNNING started_at=START+40, now=START+30
unknown=1 partial=1 valid=0
```

影响：数据质量误报；计数不守恒。

#### P2-3 `now == window_start` 时 open interval 全部丢失

证据：

- `parallelism.py:107` `interval_end = now = window_start`
- `parallelism.py:125-129` 裁剪为零长度并 `continue`
- 终态跨窗口记录不会同样丢失，造成 open/terminal 语义不对称。

#### P2-4 ROOT_MISMATCH / ROOT_MISSING 不排除但仍计入指标

证据：

- `metrics_service.py:38` `EXCLUSION_REASONS` 不含 root 类原因
- `metrics_service.py:209-215` 只记录 finding，不加入 excluded
- `tests/test_metrics_postgres.py:192-197` 断言 mismatch 记录仍被计数

影响：DEGRADED 响应中的 attempt_count / total 仍包含元数据错误记录，调用方无法区分哪些值可信。

#### P2-5 ORPHAN 无独立语义

证据：

- `metrics_service.py` 无 ORPHAN reason
- `metrics_service.py:217-220` 把父 run 不存在与跨租户合并为 CROSS_TENANT_OR_MISSING_RUN
- `delegation_service.py:589-592` 的 Step 2 anomalies 端点有独立 orphans 定义

影响：同一棵树在不同端点可能得到不一致诊断分类。

#### P2-6 ROOT_MISSING 与迁移 0016 深度上限语义冲突

证据：

- `0016_repair_agent_tree_root_backfill.py:25-27` `MAX_HOPS = 1024`
- `0016` 将超上限链写回 NULL
- `metrics_service.py:137-168` resolve 无深度上限，NULL 只报 ROOT_MISSING 并继续计入

影响：迁移层认为不可解析的数据，运行时仍被当作可计量数据。

#### P2-7 全租户无界加载与 100K bind 参数风险

证据：

- `metrics_service.py:256-259` 全 tenant delegation 扫描
- `metrics_service.py:261-273` 构造全体 run id 的 `IN (...)`
- `metrics_service.py:285-311` 全量邻接表与 BFS

影响：100K 平坦图可能超过 PostgreSQL bind 参数上限；并发请求下 DB 压力线性放大。

#### P2-8 既有 Delegation 写入路径绕过状态机

证据：

- `orchestration/delegation_service.py:308-317` mark_cancel_requested 裸 UPDATE
- `delegation_service.py:343-357` settle_terminal 裸 UPDATE
- `orchestration/models.py:27-39` 原状态机不允许某些跃迁

影响：指标基于 DB 投影状态时，异常跃迁会改变 active/not-started 分类。

#### P2-9 JWT permissions claim 信任边界需确认

证据：

- `auth.py:138-141` JWT permissions claim 合并入 principal.permissions
- `auth.py:161-162` `runs:read:tenant` 授予租户内跨用户读

说明：非 Phase A 引入，但在 ACL 审计范围内；需确认 IdP 不允许客户端自报或保留该 claim。
